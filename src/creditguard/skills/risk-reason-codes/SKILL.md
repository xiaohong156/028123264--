# 风险原因码

## 为什么需要
评分卡只给出概率，复核员需要知道"哪几个指标把它推高了"。逻辑回归的
对数几率是各特征贡献之和，因此可以精确拆解，不需要近似解释器。

## 生成规则
1. 只保留 |贡献| ≥ `min_abs`（默认 0.15）的因素，避免噪声进入话术。
2. 风险因素取贡献最大的前 3 个，缓释因素取绝对值最大的前 2 个。
3. 每条话术必须包含：指标名、实际取值、方向（推高/拉低风险）。
4. 若所有贡献都很小（总和 < 0.3），输出"证据不足"提示，并建议人工复核。
5. 话术里**不出现**"通过/拒绝/批贷"等决策动词，决策由策略技能与人工负责。

## 输出约定
```json
{
  "risk_factors": [{"feature": "pay_max", "text": "近半年最严重逾期 3 期", "contribution": 0.82}],
  "protective_factors": [...],
  "summary": "该申请被 3 项指标推高风险，主要集中在还款历史。",
  "low_confidence": false
}
```

## 已知边界
- `delay_cnt` 与 `delay2_cnt` 的相关系数约 0.98，边际系数方向不稳定，会给出“逾期 0 个月反而推高风险”的反直觉话术，因此原因码不使用该特征；模型仍保留它以利用其信息。
- 线性贡献在特征高度相关时可能互相抵消，解释的是"在当前模型下"的边际作用，
  不是因果效应；报告中需明确这一点。
- 贡献以标准化单位计算，不能直接解读为"多一元钱"的影响。
