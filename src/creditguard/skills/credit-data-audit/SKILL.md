# 信贷申请数据审计

## 什么时候用
在评分之前调用。它回答两个问题：这批申请能不能直接进入模型？
哪些记录必须退回补件、哪些可以带着风险标记继续打分？

## 规则
1. **缺失字段**：23 个原始字段中缺任何一个，记为 `error`，该记录不参与评分。
2. **无法解析为数字**：记为 `error`（例如 `LIMIT_BAL="二十万"`）。
3. **越界**：`LIMIT_BAL` 不在 [10000, 1000000]、`AGE` 不在 [18, 100]、
   `PAY_*` 不在 [-2, 8]、金额类字段为负或超出上限，记为 `error` 或 `warn`
   （金额类越界记 `warn` 并截断，因为可能是录入单位错误）。
4. **未知类别编码**：`EDUCATION ∉ {1,2,3,4}`、`MARRIAGE ∉ {1,2,3}`，
   记为 `warn` 并映射为"其他"，不阻断评分。
5. **重复申请号**：同一批内 `ID` 重复，记为 `warn`（可能是重复提交）。

## 输出约定
- `status`：`ok`（无问题）/ `warn`（可评分但需人工关注）/ `error`（退回补件）
- `flags`：机器可读的标记，如 `missing:AGE`、`range:AGE=15`、`unknown_code:EDUCATION=5`
- `summary`：计数，供 Agent 决定整批是继续、部分继续还是整体退回

## 边界
- 只做"格式与取值"层面的检查，不判断材料真伪，也不做反欺诈。
- 不修改用户输入，只返回标记与建议；清洗动作由调用方执行。
